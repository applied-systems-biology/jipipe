# WI #1376 - Implementation plans (index)

Design: `docs/superpowers/specs/2026-11-21-1376-acp-capabilities-design.md`
Investigation: `docs/investigations/1376-acp/investigation.md`

The design covers two subsystems that ship independently. Build them in this order
(one branch each):

1. **Capability system** - `docs/superpowers/plans/2026-11-21-capability-system.md`
   (6 tasks): registry model and derivation rules, ranked candidates and the MCP
   answer shape, requirement expansion with equivalent selection, plugin registration
   API and service component, artifact-backed providers with the `ai:embedding` /
   `ai:mcp` / `ai:acp-client` tenants, and the `get_capability_status` /
   `list_capabilities` / `install_capability` operations. Engine plus a minimal
   settings-store surface; no dependency on ACP.
2. **ACP client and AI panel** - `docs/superpowers/plans/2026-11-21-acp-client-panel.md`
   (16 tasks): SDK dependency and launch configs, connection manager, fs sandbox,
   session records and transcript, update translation, restore ladder, session
   manager, JIPX `ai-sessions` part with format version 2, the full AI settings store
   page, the agent catalog and installer, the chat UI extraction, the panel dock,
   the permission presenter and bridge, ready-to-use prompts with the stdio proxy,
   and the `acp:agent` capability probe.

Plan 2 depends on plan 1's plugin registration API and query types; do not start it
before plan 1 merges.

Branch naming (AGENTS.md): `1376-capability-system` and
`1376-acp-client-and-ai-panel`.
